_Updated after the follow-on sprint, 7 November 2026. The referenced original SOW was unavailable, so this is PRD traceability, not a claim of SOW sign-off._

## Status key

**Implemented** means evidence exists in the current repository; it does not imply deployment or production readiness. **Partial** means only a subset or a constrained foundation exists. **Not started** means no substantive implementation was found. **Decision needed** means the requirement is underspecified and should not be guessed. Web and API status are called out where useful. Current local runtime may include uncommitted work; refresh/session items below are marked accordingly.

## Scope and phase decisions required

1. Reconcile PRD §4 priority labels with §10 Phase 1 deliverables and engineering roadmap; explicitly decide whether Phase 1 includes account conversion.
2. Resolve authorization “Confirm” cells and user/record visibility before seeding feature grants.
3. Define lead lifecycle, duplicate handling, BANT scale, ToR template/signing evidence/approval, quote numbering, and billing rules before implementing dependent models.
4. Select email, PDF, signature, storage, payment, messaging and accounting providers; record costs, contracts, credentials ownership and sandbox access.
5. Set privacy/retention, audit retention, backup encryption/location, RPO/RTO, and data migration acceptance.
