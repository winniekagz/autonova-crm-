# ADR-002: PostgreSQL with Prisma

**Status:** Accepted · 2026-11-07 (technology confirmed by the project directive)

## Context

Relational, transactional domain with money, immutable contractual records and audit requirements.

## Decision

PostgreSQL 16 and Prisma 7 (`prisma-client` generator, `@prisma/adapter-pg` driver adapter, migrations via Prisma Migrate). The generated client lives in `apps/api/src/generated` and is git-ignored (regenerated by `prisma generate`, wired into build/typecheck/dev scripts). Constraints Prisma cannot express (CHECKs, partial uniques, triggers) are hand-written in migration SQL and marked `MANUAL`; tests prove they work.

## Alternatives considered

TypeORM/Drizzle (not chosen: directive fixes Prisma). MySQL (weaker constraint and JSON/partial-index support). Using Prisma `@default(uuid(7))` for time-ordered keys instead of random v4.

## Consequences

- Prisma 7 requires `prisma.config.ts` (no implicit `.env`) — the root `.env` is loaded there and in the seed.
- Integrity that matters (audit append-only, signed ToR immutability) lives in the database, not only in app code.
- Prisma types must stay in the API; DTO mapping is required.
- Risk: Prisma 7 is new (8.0 is in release-candidate). Pinned to 7.10.1; re-evaluate when 8 is stable.
